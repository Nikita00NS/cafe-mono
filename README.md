# Кафе «МОНО» — сайт и панель заказов

Профессиональный сайт кафе с японской, итальянской и европейской кухней: меню, комплексные обеды за 550 ₽, доставка и самовывоз, отслеживание заказа с обратным отсчётом и админка для приёма заказов.

Подробный план проекта и этапы развития — в [PLAN.md](./PLAN.md).

## Запуск

```bash
npm install
npm run dev      # http://localhost:3000
```

Продакшен:

```bash
npm run build
npm start
```

## Админка

- Адрес: `/admin` (при первом входе — `/admin/login`)
- Пароль по умолчанию: **mono2026**
- Обязательно задайте свой пароль перед запуском — см. `.env.example`:

```bash
cp .env.example .env.local
# ADMIN_PASSWORD=ваш-пароль
# ADMIN_SECRET=длинная-случайная-строка
```

Дополнительно: `NEXT_PUBLIC_SITE_URL` — адрес сайта для SEO (OpenGraph, sitemap).

## Что умеет

**Для гостя**
- Меню из 55+ позиций с поиском и липкой навигацией по категориям
- 5 вариантов комплексных обедов за 550 ₽
- Корзина, доставка/самовывоз, оплата наличными, картой или переводом
- Проверки на сервере: телефон, адрес, минимальная сумма, стоп-лист
- Страница заказа `/order/M-1042`: обратный отсчёт, прогресс, этапы, состав, сумма — обновляется автоматически

**Для владельца**
- Доска заказов в 4 колонки с автообновлением каждые 4 секунды
- Таймер до готовности на каждой карточке, подсветка опозданий, кнопки ±5 минут
- Статусы: Новый → Принят → Готовится → Готов → В пути / Выдан → Выполнен (или Отменён)
- Звуковое уведомление о новом заказе
- Стоп-лист в один клик, пауза приёма заказов
- Настройки: часы работы, время приготовления, стоимость и порог бесплатной доставки, минимальный заказ
- Кнопка «Демо-заказ» для проверки

## Структура

```
src/
  app/
    (site)/            публичные страницы: главная, меню, трекинг заказа
    admin/             панель заказов и вход
    api/               заказы, статусы, трекинг, настройки, авторизация
    layout.tsx         шрифты, метаданные, SEO
  components/          интерфейс: корзина, меню, админка, трекинг
  lib/
    menu.ts            меню и обеды — единственный файл для правки контента
    cafe.ts            адрес, телефоны, часы, условия доставки
    db.ts              хранилище (JSON), легко заменить на БД
    orders.ts          создание заказа, статусы, таймеры
    hours.ts           открыто/закрыто по Москве, предзаказы
    auth.ts            сессия администратора (HMAC)
public/images/         фотографии (заменить на реальные)
data/db.json           заказы и настройки (создаётся автоматически)
```

## Как менять контент

- **Блюда и цены** — `src/lib/menu.ts` (`MENU`, `LUNCHES`, `CATEGORIES`).
- **Адрес, телефоны, часы, ВК** — `src/lib/cafe.ts`.
- **Фото** — положить файлы в `public/images/` и указать путь в `image` у блюда.
- **Условия доставки и часы работы** — в админке (`/admin`), без перезапуска.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/orders` | создать заказ (публично) |
| GET | `/api/orders` | список заказов (только админ) |
| PATCH | `/api/orders/:id` | сменить статус, сдвинуть ETA (только админ) |
| GET | `/api/track/:number` | публичный статус заказа без персональных данных |
| GET | `/api/state` | часы работы, стоп-лист, условия доставки |
| POST | `/api/admin/login` `/logout` | сессия администратора |
| PUT | `/api/admin/settings` | настройки кафе |
| POST | `/api/admin/stoplist` | стоп-лист |
| POST | `/api/admin/demo` | тестовый заказ |

## Хранение данных

Заказы и настройки лежат в `data/db.json` (атомарная запись, сериализация операций в процессе). Каталог можно переопределить переменной `MONO_DATA_DIR` — например, на отдельный диск или в том контейнера.

Для нескольких точек или сотен заказов в день замените `src/lib/db.ts` на Postgres/SQLite — остальной код от этого не зависит.

## Деплой

Подробная пошаговая инструкция — в [DEPLOY.md](./DEPLOY.md): GitHub Pages, свой домен и DNS, VPS на Ubuntu, pm2, nginx, HTTPS, бэкапы, Docker, разбор ошибок.

**GitHub Pages (бесплатно):** в репозитории уже лежит готовая статическая сборка в `docs/`.

```bash
npm run build:static    # пересобрать docs/ после правок меню
```

Settings → Pages → Source: `Deploy from a branch` → ветка + папка `/docs`. Поле Custom domain должно быть пустым (или содержать настоящий домен вида `cafe-mono.ru`). Адрес сайта: `https://<логин>.github.io/cafe-mono/`.

На Pages работают главная, меню, обеды и контакты; онлайн-заказ и админка требуют сервера — см. раздел VPS.

Коротко для VPS:

```bash
npm ci && npm run build
pm2 start ecosystem.config.cjs && pm2 save
# nginx: deploy/nginx.conf.example → /etc/nginx/sites-available/
```

**GitHub Pages не подойдёт:** он отдаёт только статические файлы, а сайту нужен Node.js-сервер (API заказов, админка, база `data/db.json`). Сайт на Pages откроется, но заказы и `/admin` работать не будут.

**Vercel/аналог:** сайт работает, но файловая система только для чтения — нужна внешняя БД (см. выше) либо том на Render/Railway.

## Безопасность

- Пароль администратора — только из переменной окружения, сравнение в постоянном времени.
- Сессия — подписанная HMAC-cookie, `httpOnly`, `sameSite=lax`, 7 дней.
- Защита от перебора: 8 попыток входа с одного IP за 5 минут.
- Цены и состав заказа пересчитываются на сервере, клиент не может их подменить.
- Персональные данные не видны в публичном API трекинга (только состав, сумма и адрес).
